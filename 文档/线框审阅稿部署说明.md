## 需要在 GitHub 完成的一次设置

1. 打开 [migo-portfolio 的 Pages 设置](https://github.com/Migo1203/migo-portfolio/settings/pages)。
2. 在 **Build and deployment → Source** 中选择 **GitHub Actions**。
3. 打开 [Actions](https://github.com/Migo1203/migo-portfolio/actions)，选择“部署线框审阅”。如果已有部署因 Pages 未启用而失败，可在设置完成后重跑；也可用 **Run workflow** 从 main 手动运行。
4. 等待构建和部署成功，再访问实际地址，检查页面、手机视图、语言、图组和返回路径。

如果 Source 已选 GitHub Actions，保留现有设置，核对工作流实际结果。无需提供密码或访问令牌。启用权限要求参考 GitHub 官方 [configure-pages 配置说明](https://github.com/actions/configure-pages/blob/v5/action.yml)，本轮已读取其 enablement 要求；默认工作流令牌不能代替首次启用所需权限。

## 发布内容与来源

| 内容 | 来源与用途 |
| --- | --- |
| `index.html` | 从 `线框/第一版/线框审阅.html` 原样生成，作为站点入口 |
| `.nojekyll` | 静态发布标记 |
| `部署清单.json` | 记录源路径、SHA-256 与实际发布文件范围 |

不将整个仓库上传为站点，不复制 NED 原作品素材。HTML 继续使用灰框；“查看说明”和“查看来源”链接指向 GitHub 文档，避免网站根目录变更后相对 Markdown 链接失效。

网页使用 noindex 标记说明其审阅用途，该标记不是访问控制或保密措施。站点按公开审阅发布；不含真实联系表单、用户提交或后台服务。

## 发布与后续更新

- [生成脚本](../脚本/生成线框发布文件.py)只使用 Python 标准库，将输出写入指定目录；源 HTML 是唯一维护入口，避免另存手工修改的上线副本。
- [发布工作流](../.github/workflows/部署线框审阅.yml)在 main 上的 HTML、生成脚本或工作流改变时运行；普通文档变更不触发重复发布，也可手动运行。
- `.github/workflows` 是 GitHub 自动识别所需路径；工作流与脚本文件名沿用中文。
- 不设置自定义域名、不启用付费服务；工作流只为部署任务申请 Pages 写入与身份令牌权限。
- 手机首次打开时默认使用手机线框；指定 device 参数时以指定视图为准。原型仍按两种审阅尺寸工作，不代表正式网站响应式已完成。
