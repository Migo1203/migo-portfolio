# 网站专业术语与 H5

整理日期：2026-11-10。对应问题：Wireframe、建站专业名称、H5，以及这些内容属于哪些专业和行业。

## 规划与设计术语

| 名称 | 中文与含义 | 本项目的例子 |
| --- | --- | --- |
| Brief | 项目简报：说明目标、受众、范围与约束 | 求职优先、双语、首发页面与品牌来源 |
| IA / Information Architecture | 信息架构：组织内容分类、层级和连接 | 哪些信息属于作品详情、关于或联系 |
| Sitemap | 网站地图：列出页面及关系；此处指规划文档，另有供搜索引擎使用的 XML sitemap | Home、Work、Project Detail 等 |
| User Flow | 用户流程：访客为完成任务经过的步骤 | 首页 → 作品 → NED → 关于／联系 |
| Wireframe | 线框图：主要表达信息层级、布局和操作入口 | 用标题、文字和灰框安排详情页 |
| Prototype | 原型：演示界面与行为的模型，保真程度可高可低 | 可以点击导航、菜单和大图占位的审阅稿 |
| Low Fidelity | 低保真：优先表达结构与行为，视觉细节有限 | 本轮灰度、系统字体与图片框 |
| UI / User Interface | 用户界面；UI 设计关注界面的视觉和状态表达 | 后续排版、颜色、按钮及响应式界面 |
| UX / User Experience | 用户体验：访客完成任务时的整体感受与效果 | 能否顺畅理解项目并找到联系入口 |
| Interaction Design / IxD | 交互设计：安排操作、反馈、状态与流程 | 点击图片后怎样放大，关闭后回到哪里 |
| Design System | 设计系统：可复用的规则、组件与使用说明 | 后续统一字体、间距、颜色和组件状态 |
| Responsive Design | 响应式设计：根据可用空间调整布局 | 桌面分栏、手机单列及菜单变化 |

线框是表达结构的方式，原型强调模型及其行为，两者可以结合。本次审阅稿既包含低保真线框，也演示了部分交互。

## H5 到底是什么

“H5”在国内设计和营销语境中，通常指手机端传播网页，例如活动邀请、品牌互动、抽奖或滑动叙事页面。它常带有动画或互动，但这些效果不是必备条件。

这一称呼源于对 HTML5 的非正式简称。现代网页通常由 HTML、CSS 和 JavaScript 配合构成；H5 不是一种独立软件，也不等于 App 或小程序。讨论需求时，应继续说明访问环境、页面内容和交互，不能只用“H5”确定技术方案。

你的作品集可以是一个同时适配电脑与手机的响应式网站，手机访问不要求另做一套 H5。以后如有独立活动传播需求，再考虑专题页或互动页。

## 仓库、文件夹、推送与上线的区别

| 对象或操作 | 代表什么 | 不能据此认定什么 |
| --- | --- | --- |
| Git 仓库 | 文件及版本历史的管理单位 | 不代表已有可访问网站 |
| 文件夹 | 仓库内的内容分类 | 不能仅靠新文件夹实现独立仓库管理 |
| Commit／提交 | 在本地 Git 历史中记录一次改动 | 不代表已上传 GitHub |
| Push／推送 | 把本地提交发送到远程仓库的指定分支 | 不等于公开网站已部署 |
| GitHub 页面 | 展示文件、Markdown、图片和版本 | 普通代码浏览页不会直接运行 HTML 原型 |
| 部署 | 在托管环境发布网站 | 仍需检查域名、路由和实际访问行为 |

如项目配置了自动部署，推送可能触发发布；本项目目前没有将这种行为视为已配置。HTML 审阅稿可以下载后在浏览器打开，或通过本地服务查看，方法见[线框说明](../线框/第一版/README.md)。

核对一次上传时，查看仓库与分支、具体文件路径、最新提交记录和文件内容。文件标签与实际文件名可能不同，例如“NED 试验案例资料卡”沿用路径 `文档/首篇案例资料卡.md`，用于保持已有链接。

## 属于哪个专业和行业

主要涉及网站设计、数字产品设计和用户体验设计，常见于互联网产品团队、设计机构、品牌官网与电商项目。

| 专业方向 | 主要职责 |
| --- | --- |
| UX／用户体验设计 | 理解目标、访客任务与整体体验 |
| 信息架构 | 内容分类、层级与连接 |
| 交互设计 | 点击后的行为、反馈、状态与返回方式 |
| UI／界面设计 | 视觉层级、界面表达与组件状态 |
| 前端开发 | 在浏览器中实现页面及交互 |
| 品牌视觉设计 | 提供品牌表达、识别元素与规范 |

团队规模不同，职责可能由同一人承担，也可能分工协作。学习线框与原型，并不要求先掌握全部前端开发。
