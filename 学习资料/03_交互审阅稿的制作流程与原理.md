# 交互审阅稿的制作流程与原理

整理日期：2026-11-10。对应问题：“交互审阅稿的制作流程、原理、和依据，就是你是怎么做出来的。”以下描述本项目已经发生的工作；Figma 路线是下一篇中的练习建议。

## 本次用了什么方法

先整理已确认的目标、案例内容与页面关系，再编写一个独立的 HTML 文件，使用 CSS 表达灰度布局、JavaScript 演示操作。随后通过 Chromium 浏览器与 Playwright 自动化检查原型并导出截图。

实际文件：[线框审阅.html](../线框/第一版/线框审阅.html)。本轮没有使用 Figma 生成这些线框，也没有通过 AI 生图生成网页截图。正式网站的 Astro 项目尚未初始化。

## 设计依据怎样转成页面

| 依据 | 落实方式 | 状态 |
| --- | --- | --- |
| 求职优先、兼顾商业合作 | 强调作品、个人贡献与设计判断，保留联系入口 | 用户已确认目标 |
| 首页 → 作品 → 详情 → 关于／联系 | 连接导航、案例按钮与返回入口 | 用户已确认路径 |
| NED 案例内容骨架 | 按概述、分工、判断、完整成果、复盘组织详情 | 用户已确认骨架 |
| NED 原交付与版本记录 | 登记并保留四段成果与手机状态，避免混版 | 已核对，素材审阅状态另行保留 |
| 品牌资产仍为 Pending | 使用灰度、系统字体、文字标识和图片框 | 不构成品牌视觉定稿 |
| 长案例的阅读需求 | 增加章节目录、大图查看与返回方式 | 助手的线框方案，待用户审阅 |

具体来源见[案例资料卡](../文档/首篇案例资料卡.md)、[规划验收单](../网站规划验收单.md)和[任务表](../文档/下一阶段任务表.md)。本轮依据主要为用户要求、项目资料与结构判断，尚未经过真实招聘方测试。

## 实际制作过程

1. **整理事实和内容。** 阅读项目目标、分工、策略、当前成果与复盘，并查看开篇及成果预览。把 Migo 的判断工作与 AI 的执行范围分开说明。
2. **确定页面职责。** 首页介绍并导向作品，列表提供案例入口，详情解释项目，关于补充身份与工作方式，联系承接交流，404 提供返回路径。
3. **先做 NED 详情结构。** 用已确认骨架排列内容，保留完整成果，再将案例信息用于首页与列表。
4. **建立通用布局。** 复用顶部导航、页脚、章节、文字区和图片占位，分别呈现桌面和手机结构。
5. **增加交互。** 演示菜单展开、语言切换、章节跳转、大图占位及同组前后项。
6. **检查与导出。** 核对 12 份基本视图及对应英文结构草稿，检查路径和图组数量，再导出完整 PNG 与首屏总览。

桌面 1440px、手机 390px 是本轮检查起点；正式断点与完整自适应方案仍需后续设计。当前原型用设备参数选择布局，不能据此认定生产网站已完成响应式开发。

## HTML、CSS、JavaScript 怎样配合

| 部分 | 职责 | 本次文件中的例子 |
| --- | --- | --- |
| HTML | 放置内容与语义结构 | 标题、正文、导航、章节、按钮、弹层容器 |
| CSS | 决定布局和显示 | 分栏与单列、文字层级、灰框、间距、菜单显示 |
| JavaScript | 读取状态并处理操作 | 页面内容选择、语言切换、弹层打开／关闭和图片序号变化 |

原型地址参数可以写成：

```text
?page=ned&device=mobile&lang=zh
```

程序用 `URLSearchParams` 读取这些参数，决定当前显示 NED、手机结构和中文草稿。`mode=canvas` 用于导出纯线框画面；正常审阅模式额外显示页面、设备和语言选择工具栏。

文件中的 `header`、`footer` 等函数复用公共结构；`ned`、`home`、`work` 等函数提供不同页面内容；`gallery` 根据图组清单生成占位按钮。因此六类页面可以在同一份文件中维护。本轮 12 张 PNG 是该原型的不同视图导出，不是十二个独立网站。

## 点击图片时发生了什么

点击占位框后，程序记录它所属的图组与序号，打开浏览器的 `dialog` 弹层；“上一张／下一张”改变当前序号，首尾禁用相应按钮，关闭后将焦点返回触发位置。Escape 也可关闭。

当前大图仍为占位，用于体验查看行为。真实作品、触摸缩放和正式大图加载尚未接入。章节目录则通过锚点，例如 `#banners`，跳转到对应内容段。

## 怎样检查，以及检查能证明什么

实际结果见[检查记录](../线框/第一版/检查记录.json)：包括视图导出、布局溢出、图组数量、主要路径、语言切换、手机菜单和部分弹层行为检查。

- 自动化检查回答“原型是否按预设规则运行”。
- 用户验收回答“信息、布局与行为是否符合需要”。
- 目标访客测试进一步回答“招聘方能否独立完成找作品、理解贡献和联系等任务”。

这三类工作相互补充。当前检查不证明正式图片可读、实际平台 404 正确、SEO 或性能达标，也不代替完整无障碍测试。

## 如果选择代码路线学习

先学习 HTML 的内容结构，再练习 CSS 的布局与手机适配，最后用 JavaScript 增加按钮和弹层。可以复制原型到练习副本，先改一段文案或增加一个占位项，观察页面和图组数量的变化，避免直接改写项目交付。

如果希望先学习设计判断和原型表达，可从[Figma 实操](04_Figma线框与交互原型实操.md)开始。两条路线都需要先理解内容、任务和点击后的结果。
