# 前端设计统一入口

此技能负责分工，不复制、不改写两套原技能。先确定用户要规划、做小样、实施还是验收，再判断这次的页面用途和已有视觉是否需保留。

| 任务 | 主导方法 | 另一套如何参与 |
| --- | --- | --- |
| 全新营销页、产品展示页，视觉方向开放 | `design-taste-frontend`：按页面类型组织主体、构图和节奏 | 需要时取 Impeccable 的项目上下文、排版、无障碍或打磨检查 |
| 作品集、阅读页、工具界面、已有品牌或局部改稿 | `impeccable`：按页面用途做判断，保留已有身份、行为与产品事实 | 仅在需要时取 taste-skill 的图像取景、首屏焦点、节奏或真实浏览器检查方法 |

## 制作前

1. 按目标环境解析已安装技能路径，读取主导技能的 `SKILL.md` 和与任务有关的参考。使用另一套时，只读需要的章节。技能或执行器不可用时，说明实际能参考什么；不静默安装或替换。
2. 用几行记录：目标、必须保留、两至四项会改变实现的设计判断、可观察的验收证据。已有规划时只补决策缺口。做构图试验时只变更待比较变量，用真实素材看代表性视口，不提前扩展到完整页面。
3. 区分质量问题和审美选择。内容真实性、可读对比、标题语义、断点溢出、交互可达与动效回退要用证据核对。整屏高度、眉题、图注、配色等先看用户确认的方向、页面用途和已有设计，再决定采用哪些参考。发生冲突时记录采用、未采用、原因和验证方法。

## 运行与记录

- 默认是**参考模式**：借用方法并做与范围相称的真实验证，不启动两套原版完整流程，也不宣称通过其门禁。两套方法意见不一致时只设一套主导；可以用对照稿检验备选，不把原版明令禁止的方案记为该原版规则通过。
- 用户明确要求**运行原版流程**时，按对应技能的真实命令和前提执行；分别报告未运行、运行错误、已运行但结果未通过、已通过。不得改检测器、伪造记录或把手工检查冒充官方运行。
- 先确认已有稿的范围和指定素材，再验证实际渲染。审阅稿、定稿、提交、推送和部署是不同状态；此入口不扩展任务授权。
