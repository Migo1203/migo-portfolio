# Sommerseth Design｜网站设计元素与案例分析

- **参考网站：** [Sommerseth Design 英文站](https://sommersethdesign.no/en)
- **分析日期：** 2026-11-25
- **用途：** 为 Migo 个人作品集的新首页 Hero 与全站规划提供参考，不是 1:1 复刻规格。
- **证据范围：** 用户在对话中提供的首页 Hero 截图；官网当前可读取的首页、Projects 档案、Services 页面和 Fried Design Co 案例正文；Dembrandt 0.41.0 报告。没有完整验证所有滚动交互、所有断点、Blog、表单与动效源码。
- **配套原始报告：** [Dembrandt_DESIGN.md](Dembrandt_DESIGN.md) · [归档说明](README.md)

> 本文把可见事实、设计解释和对 Migo 的建议分开。官网内容与视觉可能更新；这里是 2026-11-25 的研究记录，不是对网站永久状态的保证。

## 1. 网站定位与信息架构

### 网站实际承担的角色

Sommerseth Design 展示的是一个小型全栈设计工作室，而不是单一设计师的个人简历页。首页用“设计、开发、完成”的主张表达团队的能力闭环，并自述为 small full-stack design studio；其内容不仅有作品，还有 Services、Apps、客户、Blog 和 Contact 等独立业务入口。

### 可观察的页面结构

```text
Home（长页面）
├─ Hero：设计／开发主张、工作室简介、服务关键词、Projects 快捷入口
├─ About：团队与工作室背景、地点／年份与平台资质
├─ Services：六类服务
├─ How we work：了解需求 → 设计 → 开发与发布
├─ Recent projects：六个精选案例 + 查看全部 Projects
├─ Apps：自有应用与客户应用能力
├─ Clients：客户标识列表
└─ Footer：联系信息、地址、回到顶部与重复导航

全站一级入口（以目前页面可见导航为准）
├─ Projects：Selected projects 2007–2025 档案
├─ Services：服务内容与能力证明
├─ Apps：自有产品及客户应用服务
├─ Blog：文章入口（本轮未深入阅读）
├─ Contact：联系
└─ Start a project：重点项目咨询 CTA

Project detail：项目名称／类别／交付内容／参与者署名／说明与视觉成果／回档案入口
```

官网首页当前读取结果显示了上述首页章节与主导航；Projects 页以 Selected projects 档案收录跨年项目；Apps 页明确区分自有产品和客户应用服务。页面数目与页面顺序为当前可读取页面的信息架构观察，不代表每个页面的全部交互均已审计。

## 2. 首页 Hero：构图与视觉层级

### 截图可见事实

用户提供的首页截图约为 2549 × 1485 px（约 1.72:1 的截图画布，不是页面规定比例）。画面可辨识：

- 顶部一条全宽导航：左侧标志，中部 Projects / Services / Apps / Blog / Contact，右侧语言／主题样式入口和 Start a project CTA。
- 大面积近黑底上覆盖密集、规则的像素网格。
- 画面上半部中央有一组由像素方块构成的抽象图形；右上有一个标注 “THIS IS US” 的人物影像小窗。
- 下半部左侧用超大白色无衬线标题呈现 “Small studio. Pixels for breakfast.”，蓝色方块标点打断标题节奏。
- 同一水平区域右侧放置短段落，解释服务与做事态度。
- 底边有一条细分隔线及类似状态栏／索引的文字：坐标、像素计数、Projects、服务、Blog、Contact 等入口。
- 蓝色是高对比强调色，集中落在 CTA 与标题／图像中的少量像素，不大面积铺底。

### 设计解释（推断）

1. **先给态度，再解释业务。** 大标题有记忆点；右侧短文把工作室口吻翻译成具体服务，避免只剩抽象口号。
2. **像素图形不只是背景。** 规则网格与中心图形、人物窗、像素计数互相呼应，让“Pixels”成为结构语言，而非随意加的科技纹理。
3. **把导航与状态栏结合。** 画面底边的索引像工作界面或展览标注，让主要项目入口在首屏底部再次出现；这与顶部导航形成两种不同密度的导航层。
4. **水平分区制造张力。** 顶部导航轻、中心图形留白大、下方标题重；标题与说明并置，底部索引收束画面，形成从身份到内容入口的阅读路径。
5. **小面积亮蓝充当视觉标点。** 它既突出 CTA，也重复标记标题和像素图中的局部，使全页存在稳定识别色。
6. **人物图像作为“我们”的证据。** 小窗把抽象的数字像素视觉拉回具体团队，但在当前截图中尺寸很小，承担补充而非主角。

这些是基于提供截图的视觉解释，不等同于设计者公开说明的创作意图。

## 3. 设计元素拆解

| 维度 | 网站可观察做法 | 功能／效果解释 | 对 Migo 的借鉴边界 |
|---|---|---|---|
| 品牌主张 | “We design. We develop. We complete. No bull***t.” 与 “Small studio. Pixels for breakfast.” | 把能力、交付态度、记忆性口吻压缩成两层表达 | 借鉴“态度 + 能力解释”的层级，不套用工作室复数身份或原句；Migo 的主张需要来自本人真实定位 |
| 视觉母题 | 像素网格、块状图形、点状标记与坐标／计数语言 | 把品牌名称中的 Pixels 延展到背景、图形和导航标记 | 像素语言与 Sommerseth 的命名强绑定；Migo 不应只因喜欢截图就照搬整套网格 |
| 色彩 | 深色底、白色文字、钴蓝式亮色点缀；Dembrandt 抽取到主色 #1458E4、灰 #6E6E6E、浅面 #F2F2F0、深墨 #0E0E0E | 深浅高对比承载大字与像素纹理；亮蓝建立少量焦点 | 以上是参考站抽取值，不是 Migo 品牌色。Migo 可验证“中性底色 + 少量信号色”逻辑，但颜色需要与个人品牌概念和真实作品同屏测试 |
| 字体 | 大标题使用现代无衬线显示字；小标签和状态信息有等宽／像素风取向；报告识别 Geist、Geist Mono 与 Doto | 大字号表达个性，小字号营造界面／索引感 | 字体名称与像素风标签来自报告抽取，需实测字体文件、字重与中英文字符；不等于授权可用，也不保证当前页面每处都用同一字体 |
| 字号与排版 | 标题尺度远大于说明文字，标题断行明显，强调色标点嵌在文字尾部 | 形成首屏第一记忆点，并让右侧说明成为第二阅读层 | 只借层级差，不照抄具体像素字号。中文标题更宽，需重新排字、控行和测试手机换行 |
| 网格与间距 | 报告称发现自定义间距 token，断点候选为 1024 px | 显示页面可能使用自有布局系统 | 原报告给出的间距多集中于 2–12.48 px，疑似组件 token 或抽取偏差，不能当作整页边距／栏距。1024 px 也只是检测线索，不是已验证断点 |
| 形状 | 报告列出圆角 12 px、28.8 px、9999 px；截图同时可见大量硬直角像素块 | 圆角可能用于图片／控件，与像素几何形成软硬对照 | token 不代表所有页面组件都采用这些半径；需对照具体对象和实际 CSS 再用 |
| 图像与图形 | 中央抽象像素图形，右上人物图像小窗，项目页面使用多种项目视觉 | 把作者／团队、数字母题和真实项目成果放在一个场域 | 借鉴“品牌概念图形 + 真实人物／作品证据”的角色分工，别让装饰图形压过作品 |
| 信息密度 | Hero 既展示身份，也含多组导航、状态信息、人物窗和服务简介 | 丰富首屏探索感，但整体信息密度较高 | Migo 首屏主要任务是让 HR 快速理解“你是谁、能做什么、作品在哪”；若复杂像素装饰削弱这三项，就应删减 |
| 导航与 CTA | 顶部站点导航，首屏底部重复项目／服务／联系入口，另有显著 Start a project | 兼顾全站跳转与首屏快速行动 | Migo 已规划 Home 长页、Projects、Contact；不复制 Services／Apps／Blog 等没有相应内容或优先任务的入口 |
| 页面分段 | 首页章节带编号、栏目名和醒目标题，长页以不同内容任务推进 | 让长页像一连串有标签的内容单元，便于定位 | Migo 可使用清楚章节名，但不必复制编号格式；章节节奏应服从首页叙事和作品图像比例 |
| 案例档案 | 首页精选六项并提供“See more projects”；档案页汇集跨年份的项目及摘要 | 精选负责吸引，档案负责完整浏览 | Migo 的 Recent Projects 与 Projects 页可共用同一项目资料；精选数量按真实案例成熟度决定 |
| 案例叙事 | 项目页展示交付类型、行业、credits、说明、图像和相关入口；Fried Design Co 页面清楚列出 Sommerseth 与合作团队的职责 | 让读者能区分交付范围与团队贡献，而不只看最终画面 | 对 Migo 特别有用：准确写项目性质、本人职责、AI／协作者分工、结果证据；不能借用参考站的商业成果或数据 |
| 交互与动效 | 参考站案例文案公开提到页面转场、章节显现和微交互用于强化身份；但本轮没有亲自逐项测量转场时间、触发与移动端行为 | 可确认动效被当作品牌表达的一部分；不能仅据文案推断具体实现细节 | 另做交互观察：录制一次导航到项目页的过程，记录触发、首尾状态、持续时间、遮挡／共享元素、返回行为和 reduced-motion。当前不据此复刻 |
| 响应式 | Dembrandt 报告只给出 1024px 断点线索；本次没有对应全套桌面／手机截图比较 | 无法从单一桌面截图确认重排规则 | Hero 制作前要至少检查桌面与手机；不要把截图比例 1.72:1 当作响应式模块固定比例 |

## 4. 案例档案与项目案例页

### Projects 档案页

当前 Projects 页使用“Selected projects 2007–2025”作为总体时间范围，项目名称配简短说明，覆盖品牌、网页、出版、插画、动画等不同领域；资料数量较多，页面作用是完整档案而非只展示首页精选。首页另外只露出六个 Recent projects，并提供进入完整档案的链接。

**设计判断：** 首页精选与完整 Projects 档案职责分开，能兼顾首屏简洁和项目丰富度；项目类型标签帮助访客扫描不同交付类别。对 Migo 的启发是先做精选，再给完整档案入口，但不应在作品尚少时为了模仿而造多层筛选。

### 案例详情页（以 Fried Design Co 为观察样本）

官网案例正文明确呈现项目交付范围、行业、Credits、项目背景、实施方式、动画／技术细节和团队职责。文案区分了客户团队提供的 Figma 设计与 Sommerseth 的开发、动画、功能实施工作，因此署名不是装饰，而是解释案例中每个参与方贡献的证据。

**对 Migo 的启发：** 项目页应先让读者知道作品性质与本人贡献，再展开视觉过程；对 NED 等自主概念／模拟案例，应明确标出“自主项目／作品集试验”，避免让精致页面造成真实商业委托的误解。AI 执行与 Migo 的审美判断也需分开陈述。

## 5. Dembrandt 报告整合与可信度说明

### 报告提取的线索

- **颜色：** primary `#1458E4`、secondary `#6E6E6E`、surface `#F2F2F0`、on-surface `#0E0E0E`。
- **字体：** Geist 多个标题／正文层级，Geist Mono 标签，Doto 像素风层级。
- **排版候选：** display 最大值 124.8 px、其他大标题 105.6／86.4 px；正文最大约 33.6 px，另有较多 18–26 px 层级。
- **间距候选：** xs 2 px、sm 7.2 px、md 8 px、lg 8.64 px、xl 9.6 px、xxl 12 px、xxxl 12.096 px、xxxxl 12.48 px。
- **断点候选：** 1024 px。
- **圆角候选：** 12 px、28.8 px、9999 px。

### 不能直接照搬的部分

1. 这些是自动扫描报告中观察到的 CSS／样式 token，不保证每个数值都对应实际视觉角色；命名也可能来自自动归类。
2. 间距项集中在很小的数值范围，尤其不适合被误读为内容栏宽、区块间距或整页留白规范。必须回到截图、DOM/CSS 或实测才能确认其含义。
3. 字体 URL 指向参考网站资源，报告没有授权信息。不能由此推断可以复制字体文件或再分发；应核对字体许可证，或选用授权明确的替代字体。
4. 颜色来自参考网站，不代表其在所有页面、状态和背景都按同一方式使用；实际配色关系需结合截图观察。
5. 报告没有覆盖案例叙事、导航架构、具体 Hero 构图、真实动效流程与可访问性。

## 6. 对 Migo 首页 Hero 的可执行参考

不是照搬参考站的“像素风”，而是把其首页设计任务转译成 Migo 可用的验证问题：

- **第一眼身份：** 访客能否迅速理解 Migo 是个人设计师，而不是小型设计工作室？
- **主张与证据：** Hero 的一句主张是否有 Recent Projects 作为可点击的作品证据？
- **首屏 CTA：** Projects 和 Contact 是否同时可找到，求职者是否不会把 Contact 误解成只服务商业询盘？
- **图形角色：** 是否需要一个代表 Migo 的图形／角色？若需要，它是否解释品牌概念，而不是只填空？
- **视觉焦点：** 用一个强烈主标题、一个代表性项目视觉或一个原创图形即可；不要同时堆叠多套视觉母题。
- **底部快捷索引：** 只有在能降低长页浏览成本时才加入；否则顶部导航和清楚的滚动提示足够。
- **桌面／手机转换：** 桌面可测试标题与简介并置；手机优先身份、主张与作品入口，装饰层次退后。具体构图比例按设备内容验证，不用截图画布比例定死。
- **动效分开研究：** 先复盘用户喜欢的参考站真实导航转场，再做静态 Hero。静态布局通过不等于动效方向已确认。

## 7. 结论：借什么、避免什么

### 值得借鉴

- 首页主张与业务解释形成两层信息，而不是只写抽象口号。
- Recent Projects 与完整档案分工明确。
- 服务／流程／案例等长页章节各有任务标签。
- 案例用团队署名与职责字段提高可信度。
- 颜色、标题、像素／图形标记在一套品牌概念中互相呼应。
- 动效服务于识别，不与作品争夺注意力（此项来自案例公开说明，具体效果仍应实测）。

### 不应照搬

- “Pixels”相关文案、像素网格、中心像素图形和数字状态栏的整套识别组合。
- 工作室团队身份、服务菜单、App 产品、客户名单、合作案例和业绩事实。
- 未经核实的字体授权和自动提取的间距数据。
- 用户尚未喜欢或尚未明确的转场形式。

**给 Migo 的推荐方向：** 参考其信息表达的秩序和“主张—解释—项目证据”的首屏层级；视觉语言应从 Migo 本人的概念与真实作品中生成。Migo 现有规划采用首页长页面（Hero／About／Recent Projects／联系）+ Projects 档案及独立案例 + Contact 的结构，可吸收其“首页精选 + 全量项目档案”关系，而不是照搬 Sommerseth 的 Services／Apps／Blog 架构。
