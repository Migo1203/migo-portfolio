# NED V03 页面阅读节奏优化方案

日期：2026-11-20  
范围：章节内容、阅读顺序、图片显示比例与章节间节奏；本文件为优化规划，不修改页面样式或素材。

## 结论

目前的不适感不宜简单归因于“图片统一为 1600×900”。1600×900 是封面图的源像素尺寸；页面节奏问题主要来自多个桌面章节都以 16:9 作为最低高度，再叠加内容密度、图文关系与模块重复。建议封面保留宽屏表达，其余章节改为按内容自然增长，只为具体图片与展示框设定合适比例。

## 核对范围与证据

- 当前结构：`首屏A.html` 与 `首屏.css`，顺序为封面 → 项目概述及分工 → 昼夜场景切换 → 产品全貌与操作近景 → 项目参考色 → 成果职责说明 → 商品图网格／Listing 切换。
- 当前样式中，封面、昼夜场景章节、参考色章节和桌面作品展示分别保留或设有 16:9 约束／最低高度；商品图、Listing 主图则仍为方形完整呈现。产品透明抠图为竖幅，操作图为横幅。
- 可查看的 V03 浏览器截图来自 2026-11-18，能核对当时的封面与八图网格；它们早于当前新增的背景、设计说明、参考色与 Listing 模块，不能作为这些章节的最新视觉验收记录。
- 2026-11-18 的检查记录证明当时 320–1920px 视口无横向溢出、八图成功加载；这不等同于章节密度与阅读节奏已通过审阅。

## 章节诊断

| 章节 | 当前内容职责 | 节奏风险 | 优化方向 |
| --- | --- | --- | --- |
| 封面 | 识别项目、呈现灯具和进入作品 | 桌面宽屏图文关系明确；手机采用文字在上、完整横图在下，首屏长度自然增加。嵌入个人网站时还受网站顶部导航影响 | 保留横幅构图，不强行压成固定视口高度；合并页顶部导航后单独检查首屏实际可视区域与图片完整性 |
| 项目概述与分工 | 交代模拟任务、难点、成果和本人贡献 | 项目概述与分工都在深色大章节内，字段、长段落、两组清单连续出现；`min-block-size: 100svh` 容易把不同屏幕高度误当内容节拍 | 取消至少一屏的目标；概述只保留任务、核心难点与项目属性，分工紧接其后但作为较轻的次级段落，避免两个同权重的“章节开场” |
| 昼夜场景 | 对比同一产品在两种环境中的表现 | 场景本身适合宽幅，但桌面章节至少占 16:9 高度，标题、选项、图注与背景图同时争空间；文字可能被推到画面下方，视觉上像超高背景板 | 图片继续用宽幅场景，但画面高度由图像比例与文字实际高度共同决定；标题、切换控件、图注形成清晰一组，桌面切换两种图文方向，手机改为图在上、说明紧随图，不覆盖关键主体 |
| 产品全貌与操作 | 从整体轮廓过渡到具体操作 | 一竖一横素材若被同一行强行并置，横图面积会远大于全貌图；若两图同高，透明产品图可能显得过小 | 保留一竖一横，但依据原图比例分配空间；提高全貌图自身可见尺寸，操作图完整显示手与旋钮。两个图组之间用简短图注和明确间距，而不是额外增加大块固定高度 |
| 项目参考色 | 解释颜色来源与材质对应 | 当前同样设有至少 16:9；章节可能为满足画布高度而拉开色板、场景和文字，导致联系松散；在较窄桌面端又有压缩排布风险 | 以“场景来源 → 色板 → 材质细节”组成一条视觉链；高度根据内容自然增长，保留场景图和色板各自合适比例，不要求整节填满一屏 |
| 成果职责说明 | 连接设计判断与最终成果 | 表格／清单式内容再次重复前面说明；若紧接参考色之后，节奏从图像对照突然变成文字列表 | 压缩为一段过渡和四项简短职责，视觉上作为成果区的导语；避免完整重复项目概述和 Listing 文案 |
| 商品图网格 | 快速总览八张方图，并为深入查看提供入口 | 2026-11-18 桌面截图中四列方图尺寸均衡、顺序易扫读；但八张图完全等权，第一张主图和后续功能／场景图的阅读层次不够明显。手机两列自然较长，图下说明再叠加行间距会增加连续滚动长度；小图上的英文细节无法在总览中阅读，放大入口也缺少清楚的视觉提示 | 保留方图和 4×2／2×4 网格，不用 16:9 拉伸。通过克制的分组与节奏突出“先认识产品，再看功能与使用场景”，避免每张图都加重型卡片；缩短图注并贴近图片，手机收紧行距；提供明确但轻量的放大提示，保留整图放大和 Listing 切换。新分组需先在浏览器比较，不能仅为变化而改变八图原顺序 |
| Listing | 模拟真实商品详情信息架构并允许查看原图 | 商品主图、缩略图、标题、卖点、描述和规格密度高，桌面若被压进 16:9 画布会让文字与图片抢位；手机必然纵向增长，不应按首屏高度压缩 | 作为独立阅读模式展示，保留方形商品图；允许内容超过一屏。桌面优先保障主图与标题／卖点的并列阅读，长规格放在下方；手机按标题、主图、卖点、说明、规格顺序展开 |

## 建议的新阅读节奏

1. **吸引与识别**：封面只负责产品、项目名和“查看作品”入口，保持视觉停留，不塞入项目说明。
2. **快速交代背景**：项目任务与核心难点在一组文字中读完；本人工作与 AI 协作紧随其后，但降低标题与容器的视觉重量。
3. **由氛围转到证据**：先看昼夜场景，再看产品全貌与操作，接着用参考色解释视觉选择。每个图像章节只保留一条判断和一条解释，减少相同语义重复。
4. **进入成果**：将四类成果职责收束为短过渡；默认展示八图总览，点击图片放大，另设 Listing 切换入口。八图内部从产品识别转向功能证据，再到场景延展；网格本身保持轻量，避免卡片化与过密说明。Listing 是更深入的阅读模式，不把整段强行压到总览页的同一视觉节拍。

章节之间采用两种节奏交替：大图章节使用较紧凑的标题—图片—图注关系；文字章节用明确留白和短段落停顿。避免连续多个深色、满屏、高密度的“主章节”，也避免每节都以相同的英文眉题、标题、说明段开场。

## 比例与空间规则

- 比例是模块与素材的关系，不是统一的页面规范。1600×900 只记录特定素材的像素尺寸；只有封面或确有宽幅构图需要的图片适合采用 16:9。
- 章节容器按内容自然增长。桌面可设合理的内容最大宽度与章节间距，但不以 `min-block-size: 56.25cqi` 作为通用节拍器。
- 场景图使用宽幅框并按主体调整焦点；保留灯具、桌面和环境之间的关系。遇到竖屏或窄窗口，减小图框高度或改为原图比例，不用过度裁切填满固定框。
- 产品透明图使用 `contain` 并保留完整轮廓；操作图与商品图尽量按原图比例呈现。不可因追求版面齐整而让灯体缩小或裁掉手部动作。
- 八图总览、Listing 主图及放大查看继续使用方图；它们属于商品图片比例，不决定章节容器也必须是方形或 16:9。
- 手机优先采用单栏和内容自适应高度。减少叠字、避免文字压住产品关键部分；图注跟随图片，长 Listing 允许自然滚动。

## 实施优先级

1. **先解除通用整屏约束**：调整项目概述、设计说明与商品展示的最低高度，让内容而非 16:9 决定章节高度。
2. **再重排信息密度**：弱化项目背景的重复标题与字段；缩短成果职责过渡；拉开产品全貌／操作证据的层级。
3. **优化八图总览节奏**：测试组别提示、图注密度和行距；维持原图顺序、方形完整构图、放大和 Listing 入口。
4. **细调场景与参考色构图**：分别依据原图比例、主体焦点与说明位置决定模块高度，不改变素材事实或灯具比例。
5. **最后校准 Listing 和移动端**：保持总览与 Listing 双模式行为，按真实阅读顺序检查纵向长度、切换入口可见性和图片完整性。

## 下一轮浏览器验收

- 使用当前代码和素材生成一组新的、注明日期的浏览器截图；旧的 2026-11-18 记录只作历史对照。
- 桌面检查 1440×900、1280×800 与 1920×1080；手机检查 390×844、320×568；另检查 200% 字号或浏览器缩放。
- 除溢出和可访问性外，记录每节顶部／底部坐标、自然高度、图片可视主体和图注位置，确认节奏变化来自内容层级而非拉伸留白。
- 逐项确认：场景切换时图文同步；全貌图灯罩至底座完整；操作近景手与旋钮清楚；参考色来源与材质有对应关系；八图放大、Listing 切换及返回均可键盘操作。
- 八图总览验证：桌面仍能一眼扫完四列，手机图注不过长、两列间距不过松；分组能帮助理解顺序但不制造多余容器；放大和 Listing 入口可见并可键盘操作。
- 人工复核长页连续滚动：封面后背景说明不过满；背景到场景有停顿；连续图片章节不显拥挤；参考色后能自然进入成果；Listing 不被视口高度截断。

## 决策边界

本方案是基于当前源码、规划和已有浏览器记录形成的优化建议，不代表新布局已制作或验收。需要保留的既有内容、照片、场景切换、八图放大与 Listing 操作均不在本次规划中被取消；具体缩短文案应以用户已有项目事实为准，不自行新增或改写事实性主张。
