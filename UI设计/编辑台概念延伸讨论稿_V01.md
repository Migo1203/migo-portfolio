# 个人网站概念延伸讨论稿 V01｜编辑台 × 档案与试卷

日期：2026-11-26  
状态：讨论稿，待 Migo 审阅；不是视觉定稿或网页样稿。  
范围：讨论如何将视频分析中的“借概念、借结构、借质感”，Sommerseth Design 网站案例与 Migo 已提出的“编辑台”概念结合为个人网站方向。本稿不制作页面、不确定最终文案、字体、色彩或动效，也不修改 Pages。

## 1. 讨论起点

Migo 提出的全站架构为：

```text
全站导航
├─ 首页（长页面）
│  ├─ Hero：品牌主张与快捷入口
│  ├─ About：个人介绍
│  ├─ Recent Projects：精选项目
│  └─ 联系方式 / 页脚
├─ Projects：个人项目档案
│  └─ 独立项目案例页
└─ Contact / Start a project：联系与项目入口
```

视频分析提出一套“借法”：

1. **借概念**：从与自己有关的熟悉物件或场景提炼概念。
2. **借结构**：把参考信息的组织顺序转成自己的作品集阅读顺序。
3. **借质感**：从真实物件提取能够强化概念的细节。

视频记录中讨论过“档案＋试卷”作为可能概念，因为它可以说明整理需求、分析问题和提出解决方案的能力。这里继续把它当作**讨论方向**，不视为已经定案的品牌定位。

## 2. 一个可讨论的总概念：编辑台

建议把“编辑台”理解为**整理、判断和完成视觉工作的方式**，而不是必须画一张桌面、摆放文具的具象场景，也不是“温暖编辑式”视觉风格的回退。

在这个解释里：

- **档案**负责收纳：项目是什么、背景是什么、Migo 负责什么、最后完成了什么。
- **试卷／校样**负责检视：问题是什么、观察到了什么、做了什么判断、为什么选这个方案。
- **编辑台**负责组织体验：访客像在查看一组经过整理的视觉项目资料，既能快速浏览成果，也能按需深入了解判断依据。

这一概念能否代表 Migo，仍要通过实际作品与访客理解来验证；它目前是组织网页内容和视觉线索的候选概念，不是正式品牌口号。

## 3. 视频里的三个“借”如何落到网站

| 方法 | Migo 网站中的转译 | 可尝试的表达 | 不应误读为 |
|---|---|---|---|
| **借概念** | 将“档案＋试卷”转译为“一个能看见视觉问题如何被整理、判断并完成的工作台” | 首页主张与作品证据相连；案例把问题、设计判断和结果对应起来 | 把网站做成考试网站，或将“编辑台”变成真实桌面摄影主题 |
| **借结构** | 参考 Sommerseth 的“主张／解释／项目证据”关系，并遵循 Migo 自己的导航架构 | 首页 Hero → About → Recent Projects → 联系；Projects 档案 → 独立案例；案例讲背景、贡献、判断与成果 | 复制 Sommerseth 的 Services、Apps、Blog 栏目或把工作室结构套给个人设计师 |
| **借质感** | 从档案、索引、校样等真实工作材料里筛选视觉线索 | 编号、索引标签、页边批注、分栏、校样标记、纸张或半透明叠页等少量元素 | 必须用牛皮纸、复古印章、红笔涂改、手写字体；或照抄参考站的像素网格和蓝色方块 |

## 4. Sommerseth 案例中可借的“方法”

结合[网站设计元素与案例分析](案例拆解/Sommerseth%20Design首页分析/设计元素与案例分析.md)，适合借鉴的是信息表达的方法，而不是整套外观：

- **Hero 的信息层级**：有辨识度的主张先建立印象，旁边的简短解释说明业务，项目入口让主张有作品证据。
- **首页精选与完整档案分工**：Recent Projects 用于快速发现，Projects 档案负责完整浏览，二者进入同一项目详情。
- **案例的职责说明**：通过项目内容与 Credits 交代谁完成什么，让作品的真实性和个人贡献可判断。
- **长页面章节有各自任务**：每段都有清楚主题，滚动浏览不是把内容无差别地堆在一张长画布上。
- **视觉语言成系统**：图形、文字标点、色彩与导航互相呼应；Migo 应从自己的概念发展对应系统。

不建议照搬 Sommerseth 的像素母题、人物窗位置、蓝色标点、字体名、数值、底部状态栏、文案或工作室导航。Dembrandt 报告是样式线索而不是复刻规范；它的间距 token 需要复核，字体链接不等于使用授权。

## 5. 放到 Migo 首页的可能阅读体验

### Hero：先认识 Migo，再看到作品入口

- **身份层**：说明这是 Migo 的个人作品集，不暗示自己是设计工作室。
- **主张层**：用一句暂定表达让访问者知道 Migo 如何看待设计工作，例如“先看清问题，再做出视觉”仅作讨论句，不是定稿文案。
- **解释层**：简短交代关注视觉设计与 AI 辅助创作，但不在开场把个人定位限定成电商视觉。
- **证据层**：以一张真实项目视觉或项目档案卡片承接主张，提供进入 Recent Projects／Projects 的明确入口。
- **快捷路径**：Projects 与 Contact 可见；求职与商业合作都能找到适合的联系入口。

### About：介绍做事方式，而不是重复 Hero

说明个人背景、能力范围、工作方式与 AI 在项目中的实际位置。这里可用简短的“观察—判断—制作”线索帮助阅读，但不必把所有工具或过程都罗列成流程图。

### Recent Projects：精选证据

用少量已确认可展示的真实项目证明能力。每个项目可借用轻量“档案头”表达名称、项目性质、年份与角色；不把未完成、概念试验或模拟项目伪装成真实委托。首页精选与 Projects 档案共用同一案例来源。

### Projects 与独立案例页：档案索引和项目阅读

档案列表帮助访客快速定位项目；独立案例页再展开项目背景、任务、Migo 的职责、设计判断、AI 协作方式、成果与复盘。具体顺序随项目类型调整，不强迫所有项目使用一套电商页面结构。

### Contact / Start a project：不同来访目的都有入口

联系页应兼顾招聘沟通与商业合作。`Start a project` 可作为合作 CTA，但不应让求职者以为网站只面向客户询盘；联系方式和表单内容以 Migo 提供并核实的信息为准。

## 6. “编辑台”视觉质感的控制原则

建议先把“编辑台”当作**视觉语法**而非固定皮肤：

- **信息标记**：编号、项目标签、边注、目录索引，用来帮助定位内容，不做纯装饰。
- **层次关系**：大标题、窄栏说明、项目图像、档案元信息形成明确的主次。
- **材料线索**：可从真实项目文件、校样、纸张边界、对照稿中提取一两种细节；材质效果要克制并服务内容。
- **作品优先**：装饰系统不能遮挡项目图，也不能让访客误以为效果图、流程图或模拟图是商业交付事实。
- **视觉可变**：案例内部保留项目本身的 VI，网站外层提供导航和索引，不强行把不同作品改成同一种色彩与质感。
- **品牌待定项**：具体背景色、强调色、字体、Logo、Beedog 及辅助图形仍按品牌项目的确认状态管理，不能因为本稿而定稿。

因此，暖白纸感、深墨、校样红或其他色彩都只能作为后续比较变量；不因“编辑台”三字预设某套色板，也不恢复用户已不喜欢的“温暖编辑式”风格。

## 7. 下一步讨论顺序

本稿完成的是概念组合讨论，不要求一次回答全部视觉细节。后续可以依次讨论：

1. “编辑台”对 Migo 的准确含义是什么：整理信息、观察问题、比较方案、做出判断，还是把创作推进到完成？
2. “档案＋试卷”是否仍适合作为编辑台内部的结构隐喻，还是保留其中一部分即可？
3. Hero 要让 HR 第一眼记住哪一项能力，并用哪个现有项目作为证据？
4. 选择少量真实材料线索，制作 Hero 方向比较；此时再讨论颜色、字体、图形和布局。
5. 方向经审阅后，再扩展首页长页与 Projects／Contact 的具体页面结构；转场另依据实际参考观察，不从静态图推断。
